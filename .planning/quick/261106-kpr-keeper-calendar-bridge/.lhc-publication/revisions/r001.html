Цель и результат

Цель

Владелец хочет отправлять карточку доски с датой/временем в календарь Keeper кнопкой «В календарь»; v1 строит безопасный серверный мост, UI и тесты в состоянии «не подключено» — без токенов и выдуманных записей.

Что будет работать

В карточке с дедлайном появляется секция «Календарь»: длительность, отключённая кнопка «В календарь» с честным состоянием «Календарь не подключён» и ссылкой на Keeper; серверный мост и хранение event_id готовы включиться сразу после реального OAuth владельца без повторных доработок.

Как проверим

  • Запускаем vitest для новых keeper-тестов и полный npm test + lint: видно 401 без cookie, 403 с bearer, 503 keeper_disabled без env, 409 keeper_not_connected без креда, 400 без dueAt; повторный POST отдаёт тот же eventId без второго вызова Keeper; PATCH вместо дубля при изменённом времени; идемпотентный DELETE; в UI кнопка В календарь disabled с подписью Календарь не подключён и рабочей ссылкой на Keeper. Прод-деплой не делаем до сообщения координатора и реального OAuth владельца.
  • Тесты моста: без cookie — 401; с Authorization [скрыто] 403; без KEEPER_API_URL — 503 keeper_disabled; без креда пользователя — 409 keeper_not_connected; без dueAt — 400.
  • Идемпотентность: повторный POST с теми же start/end/title возвращает тот же eventId без второго вызова Keeper; изменение времени делает PATCH, а не новое событие; повторный DELETE без привязки — идемпотентный 200 без вызова Keeper.
  • UI: в карточке с dueAt видна секция Календарь с длительностью и отключённой кнопкой + ссылкой на Keeper publicUrl; без dueAt секции нет; ни один [скрыто] попадает в frontend или Markdown.
  • npm test и npm run lint зелёные; merge в main и push выполнены; прод-деплой не делается до сообщения координатора и реального OAuth владельца.

Это декларация плана. Статус задач сам по себе не подтверждает приёмку результата.
